# R2 v2：真实多版本发布工程验收

A轮完整13阶段通过，原始请求、实例/profile身份、故障注入、释放及恢复记录可复核。它建立的是本机单GPU双版本的工程功能资格；不是生产容量、业务可用、双节点集群或持续学习结论。

## 实际结果

| 项目 | 本轮证据 |
|---|---|
| 两套真实参数 | 固定Qwen3-0.6B与Qwen3-1.7B；按tensor内容取得不同参数摘要，完整工件核对装载清单 |
| 单版本预资格 | 初始两版本、退休后重载、故障后重载共4次，每次4/4；覆盖正常/重复/流式/预算截断及释放 |
| 每版本入口一致性 | 实际wire payload及输入token IDs与各自直连一致；两次观测的独立直连与入口内容也相同；完整响应及流片段与账本一致 |
| 过载 | 16次到达中5次完成、11次429；拒绝进入分母 |
| 取消 | 已出现实际生成内容后断开，确认FINISHED_ABORTED及目标请求释放 |
| 在途切换 | 计数/队列合同另有软件反例；真实流式与已排队请求留在旧实例，新请求进入新版本 |
| 灰度 | 16次观测各版本8次；只陈述该样本，不保证小样本精确比例 |
| 回滚与退休 | 存活合格旧版本可回滚；排空前退休拒绝，退休后直接回滚拒绝；实际停止、重载、重新资格后才能回滚 |
| 控制者崩溃 | 原调用保留unknown，不补发；重启去重仍有效 |

| 活动worker在途退出 | 首个内容片段后按确切进程组SIGKILL；原调用failed，旧代际退出确认后解除租约；没有静默重试 |
| 活动实例恢复 | 显式rebind并重新资格后仍不自动接管旧active路由；显式新路由提交后才恢复，原去重键仍409 |

## 原应用结论未改变

两个旧v1记录均仍为failed、3/8，原receipt摘要与panel摘要写入新资格、版本身份、请求路由、发布事件和最终报告。它们明确是原v1条件下的结果，不是对新profile进行过应用评价的声明。没有重跑v1、去围栏改分、增加训练或以同参数改名凑版本。

现有两模型只是本地工程测试版本。后续业务负载仍须独立确认模型能力与输出合同；R3不能从本次工程通过推导业务质量，研究Q2/Q3也未因此完成。

## 实现和审查

新增不可变serving profile，固定模板/模式、引擎、dtype/量化、EOS/停止、有效采样/seed、上下文/输出上限及实现摘要。维护者配置变化须新资格；实际wire参数与输入token IDs留证。v2运行合同写入数据库，旧v1→v2及旧R1入口→v2的错误使用均在recover前拒绝，原在途状态不被触碰。

独立审查补齐了旧R1入口的scope保护、large的入口对照及活动worker在途退出。原故障注入assert有异常分支可能跳过的缺口：A轮结束后加强独立断言，未改动作逻辑；A原源码保留，收口审计另核实际SIGKILL文件与在途worker身份。没有为了源码收尾重复GPU试验，也没有把两个不同执行版本的场景拼接。

最终Windows109项通过/1项平台跳过，Linux110项通过。CPU测试、真实执行和消费核验各自承担证据，不互相代替。
