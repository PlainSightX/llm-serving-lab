# R1：本机Linux真实推理服务资格

本轮落实固定版本单实例服务，使用本机WSL2与RTX4080 Laptop GPU，无云实例或付费API。Qwen3-0.6B仅用于路径资格；R1不证明业务能力、持续学习收益、系统加速或双节点集群交付。

## 环境与实际实现

Python3.12.14、vLLM0.11.2、PyTorch2.9.0+cu128、Transformers4.57.1，完整锁在environments/serving-linux/uv.lock。独立Linux环境位于$HOME/.local/share/llm-serving-lab/serving-venv，没有替换系统Python、Windows trainer或其他项目环境。基座为已准备的Qwen3-0.6B固定revision c1899de289a04d12100db370d81485cdf75e47ca。

实现engine/engine_probe、runtime、online及启动/探针脚本：固定参数和worker启动身份、每次到达记录、持久化客户端去重、有界输入/前处理/排队/执行、包含下游发送的期限、独立请求终态与引擎清理状态、控制者恢复核对。Lab及原P0/P1/P2入口未修改。

释放探针通过插件白名单包装固定版本Scheduler._free_blocks：原方法返回后读取请求KV引用和请求表状态，并附worker代际和实际PID。它不改变调度、KV分配或参数，不是系统优化成果。API侧abort日志、总显存下降或聚合idle都不单独算取消成功。

## 完整B轮证据

工件目录：artifacts/r1-qualification-20261102-b。summary.json中14类场景全部通过；qualification-input.json保存运行源码、配置及锁快照，结束时21个源文件摘要匹配。

| 场景 | 实测结果 |
|---|---|
| 普通／流式请求 | 完成；输入token计数与引擎一致；流结束与usage保留 |
| 重复客户端键 | 返回409，重复到达独立入账，没有新增推理尝试 |
| 未配置模型／输入token／消息数量／字节上限 | 分别返回404／422／422／413，派发前拒绝 |
| TCP首段后断开 | 取消前请求未完成；记录cancelled，随后对应FINISHED_ABORTED、request_absent=true、after_blocks为空；观察到确认约60ms |
| 过载 | 24个并发到达，18个完成、6个429，拒绝也进入记录 |
| 控制者崩溃 | 在已派发、仍生成时终止自有进程；复用原runtime恢复为unknown，核对释放后ready；同客户端键仍409 |
| worker退出 | 保留部分输出，服务停止ready；无释放回执时保留unconfirmed，不假定资源已清理 |
| 同端口新worker | 新引擎启动后旧绑定仍503；显式新binding并核验旧代际进程退出后恢复200 |
| 期限及排队到期 | 独立0.35秒资格配置下5次均504，其中4次在派发前到期；已派发请求的取消释放得到确认 |
| 直连／薄入口配对 | 三对使用相同输入和解码条件，输出与token数匹配；只检查测量路径，不作加速结论 |

主runtime共39次到达，deadline-runtime另5次，共44次服务到达，不是44次模型生成。主runtime派发27次、期限配置派发1次；此外存在独立直连/校准请求。最终两个runtime的已派发尝试均无未确认清理。worker故障瞬间的unconfirmed及后续核对事件都保留，原场景JSON未覆盖。

配对耗时（毫秒）原值：direct 115.76/27.97/26.55，gateway 69.07/68.02/67.37。三对不足以做性能推断；首次预热、WSL、DrvFS持久化、探针和输出形态均影响耗时。本轮使用enforce_eager和0.55显存预算，R3必须另建合理配置与留出负载的性能基线。

## 失败、审查与修复

初次网关把安装过插件的临时模型检查进程也当成长期worker，发现该进程已退出后拒绝启动。修正为以真实请求释放证据确认Scheduler身份，原启动日志保留。

独立代码审查关闭四项重要问题：断开与资源获取同时完成时的所有权竞争、下游背压没有期限、健康检查处于容量上限之前、控制者重启前binding漂移。另补整体清理宽限、历史释放索引有界化、所有自有进程停止核验及失败流原始事件保存。

A轮已有12场景通过，但替代worker端口预检报Address already in use，整轮未完成。复查无存活监听者且原API/Core已退出；Linux socket回归复现TIME_WAIT重绑定差异，预检改为SO_REUSEADDR，并验证仍拒绝活跃监听。A轮完整目录与错误原样保留；B轮是新身份的完整重跑，没有拼接A轮通过项。

验证：Windows核心64 passed、1项Linux专用测试跳过；独立Linux serving环境65 passed。真实TCP与GPU故障矩阵独立于CPU替身测试。停止命令拒绝从Windows推断Linux进程状态。
