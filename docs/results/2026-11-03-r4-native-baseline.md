# R4原生持久化基线与候选价值判断

本轮完成了合理位置的完整基线和独立阻塞诊断。**本轮暂缓有界写入器实现，S维度源码贡献仍未完成。** 原生盘下仍有同步阻塞，不能称其消失；自动关闭候选的三个预定条件只通过两个，原判别线保持不变。

## 可信基线

整个RuntimeStore根（SQLite、payload、wire）位于实际ext4 `/dev/sdf`；两个gateway实际连接均读回WAL/FULL=2。模型/图执行、prefix cache关闭、工作负载/发生器、顺序、同GPU双模型和本地SLO与R3相同。当前profile仅实现摘要不同，有效模板/解码/参数身份与R3一致。

30窗口、1152正式请求全部发送、协议完整、调度有效，本地SLO达标1152/1152。384个直连/入口配对、192个暖发布配对的输入token、实际版本、输出长度和内容相同；三个发布均在预留空档内确认。768份正式gateway wire、800条账本（control592/treatment208）、540项原生指标差分均已复核。所有账本到达均completed、cleanup confirmed、lease released。

| 模型 | 到达率 | 配对首内容额外等待中位数：gateway减direct |
|---|---:|---:|
| 0.6B | 1 req/s | 19.119ms |
| 1.7B | 1 req/s | 18.493ms |
| 0.6B | 8 req/s | 20.124ms |
| 1.7B | 8 req/s | 39.282ms |

高负载差异仍包含入口/引擎排队政策，三个重复窗口波动较大。正式终止为20 stop/1132 length；长度预算是合成负载设计，不表示业务完成。与历史R3的18/1134略有差异；跨运行、跨时点的差异不能直接归因于存储迁移，更不是源码优化收益。三个重复窗口不等于独立硬件复现或生产容量承诺。

## 独立诊断与判别

另32请求诊断全部协议合格、释放确认、排空，追踪5.854973秒，320个同步方法区间共0.309923秒，内含256个事务退出区间共0.278266秒。线程、单调区间、arrival关联和准确runtime位置已核验。两组时长嵌套，不能相加，也不是CPU百分比。

| 事前条件 | 实际结果 | 是否通过 |
|---|---|---|
| 两个低负载配对中位额外等待≤20ms | 19.119/18.493ms | 是 |
| 低负载全部满足本地SLO | 全部满足；本轮高负载也全部满足 | 是 |
| 同步方法区间/诊断跨度≤5% | 5.2933% | 否 |

判别脚本保留`close_current_writer_candidate=false`，没有把5%事后放宽为6%，没有把事务子区间代替全部方法以获得通过。

当前选择是**暂缓实现，候选等待目标负载的价值证据**。原生盘下当前正式负载全部达标，已确认的同步区间约每诊断请求9.69ms；这个单一短窗口既不能证明写入器没有收益，也不足以证明新增调度层值得。异步写入仍须等待派发前持久确认；ReleaseController的route读取、资格检查与lease绑定还需同序原子化。一个有界队列同时必须解决“队列满仍记录全部到达”和“等待者不能无界”的冲突，取消/关机也不能遗失已排入命令。简单套to_thread不满足这些要求。

后续先围绕既定双独立GPU节点目标明确S验证负载和收益门槛，再决定推进此候选或选择更有价值的源码问题；需要目标环境时先形成具体资源/费用方案再申请云购买。R4源码收益、留出负载和对应故障回归都保持未完成，不能拿本轮配置基线替代。真实持续学习、权重更新及Q2准备缺口继续保留。

## 快照问题及修复

独立审查发现原导出使用`with sqlite3.connect(...)`，只结束事务而未显式close；runner退出时checkpoint导致native数据库字节变化、WAL/SHM消失。A轮快照是停机、无并发写入时保留的checkpoint前DB/WAL/SHM整套原件，1660份快照文件摘要一致。

通过仅复制SQLite三类文件到隔离临时目录打开，核验snapshot/native的sqlite_master和所有表/行完全相同、integrity_check通过；原件未被审计修改。非SQLite文件也与原生原件逐字节匹配。这支持逻辑一致性，不宣称原件始终物理摘要相同。

交付源码增加导出成功/失败均显式close，快照核验区分原件字节与checkpoint后的逻辑身份。真实A基线和A诊断的source快照保持原样，未补跑或冒称执行过新关闭逻辑。相关回归包含真实WAL checkpoint差异、逻辑篡改拒绝、导出错误仍关闭连接。另两项独立审查修复确保关闭候选只消费已核验原始计时，并检查诊断自身的ext4/WAL-FULL来源。

## 计数与边界

正式1152 + 24预热 + 16预资格 + 4bootstrap =1196生成请求。独立诊断另32测量+4预热+8资格+4bootstrap=48，合计1244；管理、metrics、图捕获不计入。诊断占比低于10%，没有触发额外CPU存储对照。无训练、新模型或云购买。

原件：`artifacts/r4-native-baseline-20261103-a`、`artifacts/r4-native-timing-20261103-a`；重算报告与原判别在`artifacts/r4-native-report-20261103-a`、`artifacts/r4-native-decision-20261103-a`。原生runtime保留在项目私有r4-runtimes目录供证据复核，归档证据时再审查退休；不是第二个产品或写入权威。[复现及清理说明](../r4-operations.md)。

最终检查：Windows141通过+1平台跳过，Linux142通过；正式及诊断共16个记录进程身份均退出，19080–19084端口空闲。确切六个其他业务容器仍在，未操作它们。当前判别脚本重算与首份decision逐字节一致，5%条件仍为false。
