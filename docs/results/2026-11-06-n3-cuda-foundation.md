# N3：CUDA基石实测与候选拒绝

本包完成了一次有界CUDA实现、真实模型接入及ONNX/TensorRT块级部署实验。**N3整体验收未通过，自定义算子不采用，S性能亮点未完成。** 数值容差、内存安全和实际执行路径有真实证据，但不能抵扣模型逐token一致性失败及成熟实现对照中的性能不足。

## 已取得的基石证据

| 范围 | 实际结果 | 能说明什么 |
|---|---|---|
| C++/CUDA residual RMSNorm | 81个数值场景，11类非法输入拒绝 | 固定dtype/形状/stride/舍入合同下通过检查 |
| 调用语义 | 2个独立stream、CUDA Graph、no_grad及inference_mode叶子参数 | 当前stream、原地状态和实际推理上下文通过 |
| Compute Sanitizer | memcheck、racecheck、synccheck、initcheck均零错误/危险 | 所执行形状未发现相应内存或同步问题 |
| 成熟实现对照 | 27组形状×dtype，每组5次同进程试验 | 自定义实现多数场景较慢，不能写优化收益 |
| 实际Qwen3-4B路径 | Nsight记录92,664次自定义GPU kernel执行 | 证明确实接入模型，不只是函数被注册 |
| 模型一致性 | 自定义vs成熟1/16；成熟自身重复16/16 | 预定逐token一致性门失败，拒绝替换 |
| ONNX/TensorRT块 | 实际Qwen权重，FP32，5种动态shape通过 | 只证明归一化块部署，不是完整LLM后端 |

环境是原A10、原服务镜像、Torch2.9.0+cu128/vLLM0.11.2；隔离CUDA12.8.93编译与检查工具、Nsight Compute2025.1.1。TensorRT10.11.0.33/ONNX1.19.1仅在独立前缀。默认服务没有加载实验插件，未改变原训练/推理环境。

实现采用256线程、warp shuffle与共享内存归约，对齐时每次读取两个元素，奇数尾部及不满足对齐的输入使用标量路径。支持行stride，禁止共享storage，保持原地input/residual身份。相加residual先舍入到输入dtype，再计算FP32方差；归一化结果先舍入，再乘权重，对照固定上游CUDA合同。默认Inductor的中间数值路径另列，不假定逐bit相同。

## 模型接入与拒绝边界

显式vLLM general plugin注册OOT RMSNorm，只在实验开关、固定0.11.2版本和正确二进制SHA同时满足时启用；保留无residual及其他不适用路径的上游实现。默认Inductor、上游+rms_norm、自定义+rms_norm使用相同模型、输入、解码、4096 batched-token预算和资源配置。

16组固定长度输出中，自定义与成熟实现只有1组逐token完全相同。另做一次不改变成熟实现的完整重复，16/16一致。这个对照没有观察到成熟运行自身漂移；自定义实现未满足原定一致性门。局部容差检查通过不能替代该门，也不能仅凭token差异推断业务答案质量升降。数值差异在模型中的传播尚未完成层级归因。

总计96次逻辑生成：默认20、成熟20、成熟重复20、自定义36，其中自定义含4预热、16无剖析器观察和16独立剖析。首次自定义初始化失败产生0次逻辑生成，原件保留。没有用于挑优的重复prompt或训练。

## TensorRT块级补充

取固定Qwen的第一层post-attention归一化权重，转换为FP32块，导出ONNX opset17并生成TensorRT engine。tokens为1、8、127、2049、4096的五组均通过PyTorch参考及自定义FP32实现对照，最大绝对误差约3.5763e-7；0及4097超出已设profile，被明确拒绝。

初次默认stream运行保留；按运行时提示改为显式非默认CUDA stream后重新验证全部形状。最终记录的是含主机提交间隙的CUDA event时间，不能与上面的纯图微基准直接混算。块级通过不会升级BF16完整模型一致性结果。

- 首次编译因宽泛CUDAContext头引入未安装的cusparse.h失败；改用实际需要的CUDAStream头后通过，未改设备端算法。

- 四类sanitizer及完整数值/微基准已在最终二进制上重做；模型失败与性能不足保持失败，不因修复工具链或块部署成功而升格。
