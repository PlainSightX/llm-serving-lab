## 失败、技术重复和恢复

| 运行 | 观察与处置 |
|---|---|
| A | tmpfs的noexec使动态库映射失败；属于环境故障，保留原日志 |
| B | 动态库副本累计耗尽256MB临时空间；改为每回合独立进程与临时目录 |
| C | 手写特权策略11/12通过，target06在100步内循环；原任务与预算不变 |
| 单题诊断 | 同一target06由特权planner在8步完成；不声称最短路径或公开观察可发现性 |
| D | 统一planner，完整42回合；旧版未保存独立child退出回执 |
| E | 便捷启动器完整重复；旧版仍缺独立child退出回执，不能自动升级为最新完整核验 |
| F | 补齐消费校验与child退出回执后完整42回合；容器退出0，宿主收尾被应用重启打断 |

D/E/F是同一任务切片的技术复验，不增加独立科学样本数。未拼接各轮通过项，也未更换失败题目或放宽预算。A–E及单题诊断原始工件均保留。

重启后原exec会话失效。根据F的启动记录找到确切容器，核验完整ID、名称、owner/run_id及镜像，确认全部回合完成且退出0；保存原Docker日志/inspect，逐条重核数据后回收该容器。recovery-verification.json记录恢复过程和原始文件摘要；原任务文件保持不变。原启动器未正常返回，因此没有伪造launcher-verification.json。恢复没有新增环境回合或模型调用。
